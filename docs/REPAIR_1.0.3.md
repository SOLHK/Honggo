# Honggo 1.0.3

## 版本与状态

从 `test` 的 `ea50d73`（Honggo 1.0.2）继续，插件版本递增为 **1.0.3**。产品名称仍为 **Honggo**，分发文件为 `Honggo-1.0.3.dylib`，宿主版本仍为红果短剧 **7.4.3 / 7.4.3.33**。

此版本是 `test` 的真机验收候选。下文记录改动与验收方法；实际设备构建、回归结果与系统截图以对应提交的 GitHub Actions 附件为准。属性透明本身不能证明真实玻璃已经恢复。

## 已确认的上一轮证据

1.0.2 在 iOS 26.5 的 UIKit 受控宿主中通过 **47/48** 项，剩余失败是效果视图自身存在实心背景。赋值前后观测捕获到：插件先将背景设为透明，非空 `setEffect:` 调用随后把它改成 `systemBackgroundColor`。

独立原生 Regular / Clear 参照在兼容模式开启时也呈实心背景，测试应用关闭兼容模式后显示玻璃。完整 `simctl` 截图与属性记录相互支持，不能仅归因于应用内截图遗漏了系统合成层。详细数值和失败记录见 [1.0.2 后续补记](REPAIR_1.0.2.md)。

重复布局的实际材质赋值次数没有增加。连续读取 `effect` 的返回对象身份不稳定，不能作为重新创建材质的证据；本轮继续以真实 setter 调用计数验证复用。

## 本轮局部方案

验证范围限定在插件自有的 `HGGlassBackdrop`：给它设置效果后，再清除自身被写回的实心 `backgroundColor`。这种调用顺序针对上一轮已经观测到的属性变化。

宿主的 `UIDesignRequiresCompatibility`、初始化入口和 IPA 元数据保持原样，不安装 `NSBundle` 读取拦截。玻璃关闭后仍按原先约定退出并重新打开应用，避免因本轮实验引入全局 UI 模式变更。

实现同时在后续布局中幂等维护背景，主题变更时要求一次有效布局；移窗期间阻止重新创建材质。减少透明度或增强对比度开启时保留系统背景，不覆盖这些辅助功能设置。

局部方案仍须通过视觉验收：如果实际材质在兼容模式下被抑制，清背景可能只得到完全透明的视图，必须被无效果对照检出。

## 必须补充的证据

- 继续运行既有的 48 项底栏检查、关闭开关检查、设置入口检查、设备编译及 Python 工具测试，并保留已知旧源码负对照。
- 在同一测试背景、尺寸和主题下，比较直接创建的原生效果、效果赋值后清背景的原生效果，以及 `effect=nil` 的透明对照。
- 使用完整 `simctl` 系统截图判断色彩混合、磨砂、边缘与折射是否仍存在；不能仅凭 `UIGlassEffect` 对象存在或背景 alpha 为零就宣布通过。
- 记录当前插件底栏在浅色、视频深色、列表底部及重新挂窗后的表现，核对文字、按钮、红点和滚动末项。

底栏和设置检查在两个独立模拟器任务中并行运行，设备构建与产物上传依赖两者成功。系统截图、像素比较结果和完整回归 JSON 随 CI 保留。UIKit 模拟器使用受控宿主模型，仍不替代红果 IPA 的真机验收。
