# Honggo 1.1.5 本地测试版

基线：14986da63fd3699be104d9150730a5c942c12bf2（1.1.4）。仅交付 dylib，不推送、不制作真实 IPA。

用户真机反馈：从设置返回遮罩仍存在，滚动卡顿，难以回到顶部订单区域。1.1.4 日志已经显示 Compose 透明容器 inset 保持 0，因此上一版的容器识别修复不足以解决问题。

新证据：五页横向容器 contentSize.width=2200、屏宽=440；滚动时它的高度在约 735–835pt 间被插件重写，bottom inset 在 0、27、31、50pt 等值间变化；外层 contentSize 同时变化。旧版的横向分页判断还依赖瞬时 contentSize.height，布局过渡期间会误入纵向列表补偿。更根本的问题是遍历嵌套内容的移动坐标并改变子容器布局，干扰宿主协调器对高度和偏移的计算。

本版：

- 删除 setContentOffset: 观察回调，不在每个滚动偏移更新中扫描整页。
- 不给内容视口安装动态观察子类；通过底栏和控制器原有布局入口处理页面变化。
- 遇到已确认的两种嵌套滚动协调器即停止深入，不再改变它们的折叠头部、分页和内部列表尺寸、inset 或 offset。
- 只延长外层视口；外层尺寸变化后让宿主执行一次自身布局，保留宿主的子布局结果。
- 横向分页判断不再依赖瞬时内容高度。
- 对嵌套协调器和 Compose 辅助滚动容器隐藏额外的 topEdgeEffect，并保留原值用于退出恢复；原 bottomEdgeEffect 处理保留。系统上边缘效果的接口见 [Apple 文档](https://developer.apple.com/documentation/uikit/uiscrollview/topedgeeffect)。这是对重复系统渐变遮罩的处理，不能据此认定所有白色区域均已真机消失。

本版撤回先前“深入嵌套树补偿内部列表”的策略；不再把该行为当作正确验收条件。玻璃材质、菜单白底修复和广告规则保留。

验证：6 个生产模块 ARM64 编译/链接通过（Clang 20.1.2、iPhoneOS16.5 SDK、LLD 23.1.1，-Wall -Werror）；45 项实际产物指令/结构检查通过，其中确认旧滚动 offset 回调符号已移除。旧版 1.1.3 二进制对照确认原路径存在。7 项版本工具测试通过；版本递增、bash 语法、嵌入 Python 语法及 diff 检查通过。4 个 UIKit/Foundation 测试源文件编译通过。

新增 UIKit 用例检查两种协调器的子分页几何与 inset 保持宿主所有，200 次上下滚动后 offset 回到 0，五轮移除/重新加入页面后不接管子分页，上边缘效果隐藏，以及退出后恢复外层尺寸。旧嵌套树修改断言被相应替换。

限制：指令检查使用模拟框架接口；上述 UIKit 用例仅编译，当前 Windows 环境没有运行 Simulator、Xcode、真机或远程 CI。没有测得实际帧率，没有完成订单区可达性、返回后的遮罩和视觉验收。此版为针对已确认布局干预的测试修复，需用户设备复核。

安装：移除旧 Honggo/HongguoGlass，仅注入 1.1.5，随宿主重签，彻底退出重开。重点连续“下滑到历史中段 → 上滑回订单 → 进入设置 → 返回 → 重复”。正常列表末尾的内容空白不做伪造填充。
