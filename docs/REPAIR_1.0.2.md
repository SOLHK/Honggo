# Honggo 1.0.2

## 当前状态

从 `test` 的 `bce3aae`（Honggo 1.0.1）继续。按每次更新递增插件版本的要求，本轮版本为 **1.0.2**；产品名称仍为 **Honggo**，宿主版本仍为红果短剧 **7.4.3 / 7.4.3.33**。

这份记录首先保存上一轮实际失败结果和下一轮取证方向。当前尚未确认两个失败项的根因，也尚未完成 1.0.2 的设备构建、UIKit 回归或真机验收，不能据此宣称修复完成。

## 1.0.1 的实际验证结果

GitHub Actions 中的设备 dylib 构建、Python 工具测试及设置入口回归已通过，但整个工作流因底栏回归失败而失败。底栏附件 `tabbar-suite-results.json` 与 `current/tabbar-results.json` 记录：

| 检查 | 结果 |
| --- | --- |
| 当前实现，UIKit 受控宿主 | 41/43 项通过，2 项失败 |
| 关闭玻璃开关 | 7/7 项通过 |
| 旧源码负对照 | 检测到 26 项失败 |
| 模拟器系统 | iOS 26.5 |
| 原生 `UIGlassEffect` 可用性 | 可用 |

两项失败断言的原名是：

- `material stays behind the untouched original controls`：原控件层级和材质合成关系的联合检查未通过。
- `repeated host layouts reuse the same glass and material`：重复布局后玻璃视图及材质复用的检查未通过。

这些结果证明本轮验证存在未解决的问题；目前还不能仅凭联合断言判断是具体视图层级、材质生命周期、属性读取语义或取证时机造成。其他检查通过也不能抵消这两项失败。

## 1.0.2 的诊断方向

本轮补充更细的层级、合成状态与材质复用诊断，并通过 `simctl` 获取完整模拟器屏幕截图，与应用内截图和结构信息对照。保留两项原断言要验证的行为与旧源码负对照：分别检查每个层级/背景条件，以实际 `setEffect:` 调用计数检查重复布局是否重新安装材质，同时记录连续读取 `effect` 的身份差异。不能将对象 getter 的身份变化直接当作材质重建，也不能只因创建了 `UIGlassEffect` 对象就判定视觉效果正确。

原生参照仅存在于测试宿主中，用公开 API 创建独立玻璃视图，比较兼容模式开启/关闭下的实际画面。测试不会为让结果通过而修改真实宿主的全局兼容选项。工作流将底栏检查提前到设置检查之前以便更早报告底栏失败；全部既有门禁仍须通过才上传设备产物。

版本、设置中的版本显示、分发文件名及 Mach-O 版本继续使用同一来源 `src/HonggoVersion.h`。分发文件名应为 `Honggo-1.0.2.dylib`，安装名仍为 `@rpath/Honggo.dylib`。

完成诊断后，应在本记录补充确认的原因、具体代码改动、对应提交与 CI 结果。当前记录不预先认定需要改动哪一项生产行为。

## 验证边界

UIKit 回归使用受控的 `SSTabBar` 宿主模型，并非实际红果 IPA。即使后续模拟器回归全部通过，用户设备上的视频合成、材质浓度、深浅色切换和瞬时遮罩仍需在真实红果短剧中检查。完整模拟器屏幕截图可以改善取证，不能替代真机验收。
