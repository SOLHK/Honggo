# Honggo 1.1.13：补齐播放器广告现场诊断

基线：`1487a8af4dc5faf7a3e716fe3747a1ac76a4b7e2`，Honggo 1.1.12，`test`。

## 本次问题与证据

用户截图是短剧播放流中的直播带货导流卡片，叠加“恭喜获得直减券”营销弹窗。画面有“点击进入直播间”“上滑继续看短剧”。可以确认是用户要过滤的插播营销内容，但不能仅凭画面判定其付费投放来源、iOS 控件类或网络接口。

用户提供的 1.1.12 日志显示宿主为 Eggplant 7.4.3.33。截图同一分钟仍记录短剧信息流和贴片拦截命中，相关电商和领券开关已开启。规则表的启动电商入口 `SSStartUpEcomQCPXPopupOperation` 与书城券挂件入口 `SSECommBookCouponPendantManager` 已安装，但日志没有显示这次直播营销经过它们。`HGSkipPatch` 写入的 `returnOrSkip: false` 是它主动跳过并调用 `ready(nil)` 的记录，不能解释为广告已展示。

**当前已确认规则没有直播插播专用入口；尚未确认具体漏拦截的 iOS 方法。** 原日志的 `maskScenes` 为空，导出快照是设置页。日志不采集请求 URL 或正文，不能据此猜造网络拦截规则。

## 已确认并修正的诊断缺口

旧 `MaskScene.inc` 的截屏通知只捕获 `SSMine737KMPViewController` 对应的个人页，因此播放器及直播领券弹窗不在该采集路径内。仅让用户重复导出旧日志不能补齐这项证据。

1.1.13 增加独立的截屏观察器，不依赖底栏适配成功或玻璃开关。增强诊断开启时，它从前台场景的可见窗口采集当前控制器、弹窗与视图结构；独立弹窗窗口也可进入快照。节点只包含类名、父子关系、几何和可见状态，另采集有界的非系统类方法名、ABI 与 UIControl action 元数据。

实现不读取标签文字、图片、无障碍标识、账号或请求数据，不调用任何广告按钮、任意宿主业务 getter 或滑动操作。采集结果写入现有 `maskScenes` 环，标记 `kind: ad.scene`，返回设置导出时仍保留先前现场。该环仅保留本进程最多 10 份、总计 768 KiB；退出应用会丢失现场。新模块本身限制节点、类方法、时间与序列化大小，并在超限时标明截断。

## 版本范围

- 插件名称仍为 Honggo，版本递增到 1.1.13，现有设置键不变。
- 新增的是诊断能力，**没有新增直播广告过滤规则，也没有宣称用户截图中的广告已消失**。
- 现有广告 hook、播放回调、底栏与原生玻璃实现保持原样。未制作或修改真实红果 IPA。
- 保留已有设置和底栏 CI 门禁，新增独立的 UIKit 广告现场诊断测试；设备构建必须等待三组检查通过。

## 如何补齐现场

1. 仅注入一份 `Honggo-1.1.13.dylib`，打开「我的 → 设置 → Honggo → 增强诊断」。
2. 返回播放器，在直播导流页或领券弹窗实际显示时截屏。
3. 回到设置导出日志，期间不要退出应用或清除日志。

原始 7.4.3.33 宿主 IPA 或该广告现场的类结构是下一步定位入口的必要资料。拿到入口后应核对方法编码和调用语义，在播放队列/插入决策处过滤已证实的商业内容，并验证普通短剧、主动直播、连续切集、关闭广告开关以及遮罩/音频生命周期。不能只把中间券卡片隐藏，留下直播空页或触摸遮罩。

## 验证边界

`tests/AdSceneIntegration.m` 在真实 UIKit 中构造受控播放器、弹窗和独立窗口，检查采集覆盖、隐私、资源上限与 UI 无副作用。它不是红果 App 真机测试。实际构建和各项结果以本提交的 GitHub Actions 为准；CI 成功只能证明对应构建与受控回归，不能证明直播广告已去除。

原始用户日志与截图不提交到公开仓库。
