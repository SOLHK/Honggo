# Honggo 1.0.6

## 本轮范围

从已通过完整 CI 的 `test@5d16b2411c262313b58585b5920e83599f2a0e99`（1.0.5）继续。产品名称保持 **Honggo**，插件版本递增为 **1.0.6**，分发文件为 `Honggo-1.0.6.dylib`。支持的宿主仍为红果短剧 7.4.3 / 7.4.3.33。

1.0.5 已完成回退圆角、布尔序列化和截图握手验证。本轮针对后续审查发现的独立可见性变化路径，保留既有玻璃材质与全部像素判据。

## 缺陷与局部修复

旧代码隐藏 `backgroundImageView`、`lightView`、`darkView`、`lineView` 后主要观察父视图。父视图不会接收子视图的 `setHidden:`，因此宿主直接令背景可见、尚未执行下一次布局或外观刷新时，背景可能重新露出。原有点击测试随后主动调用外观刷新，未验证这两个动作之间的状态。

1.0.6 在已确认目标属于当前底栏、不包含标签文字或控件、不是内容容器及其祖先的前提下，观察背景实例自身。仅此入口允许已知背景 `UIImageView` 使用既有动态子类机制；不更改全局 `UIImageView` 或 `UIView` 方法，不观察 `UIVisualEffectView`、UIKit 材质内部类或已有 KVO 包装类。原 setter 先正常执行，再在同一调用内清理宿主背景。既有防重入避免递归。

背景被替换或移出底栏后，先恢复插件拥有的状态，再解除属于当前底栏的观察。只有动态类仍为插件直接安装的类时才恢复原类；后来加入的第三方子类不被覆盖。这个处理避免旧背景复用时继续触发旧底栏刷新。

这是受控宿主可复现路径的修复。尚无真实红果调用日志证明用户截图中的每一次遮罩都由此路径触发，不能把它写成已经完成真机根因确认。

## 验证要求

在背景已被插件隐藏后，直接执行 `backgroundImageView.hidden=NO` 和 `lightView.hidden=NO`，立即检查背景仍被抑制，且没有靠外部布局或外观刷新补救。对相同断言运行 1.0.5 源码作为负对照，证明旧版会暴露该问题。

同时检查背景重建、移除恢复、无关图片可见性与全局 setter 不受影响。保留原有 59 项底栏行为、7 项关闭行为、10 项兼容回退、独立现代/兼容材质对照、旧源码负对照、设置入口、Python 工具和系统截图门禁。所有当前版本验证通过后 CI 才生成设备 dylib。实际计数、工具链和产物来源见本提交对应 [GitHub Actions](https://github.com/SOLHK/Honggo/actions)。

## 安装与验证边界

本版本的原生玻璃策略仍要求受支持主 App 在启动前明确配置 `UIDesignRequiresCompatibility=false`。预处理工具会验证原 IPA 并完成该配置及插件注入；仅注入 dylib 且保留兼容配置时使用系统模糊回退。这个策略不能推广为 Apple 对所有 App 的统一要求：Apple 说明 Xcode 26 SDK 构建的主 App 在系统 26/27 仍遵守该键，而 Xcode 27 SDK 构建的主 App 会忽略它。参见 [Apple 官方工程师说明](https://developer.apple.com/forums/thread/838637)。

UIKit 模拟器结果不等于真实红果 IPA、iPhone 真机或全部旧系统已经验收。原始红果 IPA 仍需提供后才能生成待签名宿主包；动态库不能单独安装成 App。升级时从原 IPA 注入本版本，避免同时加载旧 `HongguoGlass.dylib` 和新 Honggo。
