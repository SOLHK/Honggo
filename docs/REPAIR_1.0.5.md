# Honggo 1.0.5

## 版本与范围

从 `test` 的 `5aafeff280f7dab8c17e927f1fbc068863b0852d`（Honggo 1.0.4）继续，插件版本递增为 **1.0.5**。产品名称仍为 **Honggo**，分发动态库为 `Honggo-1.0.5.dylib`，宿主版本仍为红果短剧 **7.4.3 / 7.4.3.33**。

本轮修复兼容配置下系统模糊回退的胶囊裁剪，并修订验证流程。IPA 预处理行为保持原样：原生玻璃仍需要主 App 明确配置 `UIDesignRequiresCompatibility=false`；保留原兼容配置时仍采用系统模糊回退。全局设计配置和底栏开关的范围见 [1.0.4 打包说明](REPAIR_1.0.4.md)。

## 上一轮已经观测到的事实

[1.0.4 的 CI](https://github.com/SOLHK/Honggo/actions/runs/42494439254) 结论仍为失败，设备构建未放行。复核完整 JSON 后，需区分以下结果：

| 检查范围 | 1.0.4 实际结果 |
| --- | --- |
| 当前底栏预定行为 | **59/59** |
| 额外记录的系统截图确认 | `tabbar-dark`、`tabbar-scroll` 两项超时，使当前 JSON 总计为 **59/61** |
| 底栏开关关闭 | **7/7** |
| 兼容配置下的模糊行为 | **10/10** |
| 设置入口 | **21/21** |
| Python 工具与版本规则 | **20/20** |

移窗即时状态已经分项记录，效果视图 `opaque=false`，自身和 `contentView` 的背景均透明，`UIGlassEffect` 存在且视图位于预期窗口。这里没有证据支持将 1.0.4 的失败继续归因于背景恢复为实心；也不能从该轮快照推断 1.0.3 的旧联合检查究竟在哪个字段失败。

真实插件底栏在浅色、深色系统截图中，与无效果透明参照的平均绝对 RGB 差值分别为 **74.5102 / 51.1258**，最大通道标准差分别为 **41.2457 / 44.0721**。旧报告中的可见材质数值检查已经为 `true`，但控件归属检查收到 JSON 数字 `1`，Python 的 `is True` 身份判断将其误拒。详细字段与原始报告位置见 [1.0.4 后续复核](REPAIR_1.0.4.md)。

模糊回退的浅色标准差为 **7.3116**，不能直接套用玻璃的 `>8` 纹理变化判据。其 10 项行为检查通过，并不代替材质图像验收；需要独立的原生系统模糊参照来确认回退渲染。

## 兼容模糊的胶囊裁剪

1.0.4 的真实系统截图 `fallback/tabbar-material-light-system-simulator.png` 显示，兼容模式下的底栏模糊背景为矩形，四角没有形成胶囊。这个视觉问题与上面的 JSON 布尔判读错误是两个独立问题，不能通过修正测试类型消除。

源码此前只根据视图是否响应 `setCornerConfiguration:` 判断应使用新圆角接口。在该受控兼容配置下，接口虽然存在，系统模糊回退却没有按胶囊形状裁剪。1.0.5 改为按实际材质配置选择圆角路径：满足原生玻璃配置时使用 `UICornerConfiguration`；兼容模式的 `UIBlurEffect` 则对插件自己的效果视图设置 `clipsToBounds`、半高度的 `layer.cornerRadius` 和连续圆角。父视图不参与这个裁剪。

这一变更保持原有模糊样式和强度。回退的圆角形状、浅深色材质以及四个标签和红点，需要由本版本的公开配置检查与系统截图共同验证；此前的矩形截图不能充当修复后的结果。

## 本轮验证要求

- 统一验证 JSON 的布尔字段契约，保证 Objective-C 表达式的装箱结果能被 Python 严格判读。原控件父级、可见性、效果类型和材质层级仍必须满足原条件。
- 修订系统截图请求与确认的同步过程，完整记录每个必需阶段。截图文件存在不能代替收到对应阶段的确认，也不能掩盖超时。
- 为模糊回退增加同主题、同尺寸、同背景的独立系统 `UIBlurEffect` 参照，并继续保留无效果透明对照。按原生模糊参照验证实际回退材质，原生玻璃的判据保持独立。
- 核对原生玻璃和系统模糊各自的胶囊圆角路径，确认回退只裁剪插件自己的效果视图，并在系统截图中检查四角与原控件显示。
- 继续运行当前底栏行为、关闭开关、设置入口、原生玻璃参照、兼容模式负对照和已知旧源码负对照，保留完整系统截图与像素报告。

这些修订须在新的 CI 中重新执行。1.0.4 的原始失败记录和附件保留，不能用后处理的解释替代 1.0.5 的正式验收。

## 构建与交付

版本号仍由 `src/HonggoVersion.h` 单点管理，设置页、日志、分发文件名和 Mach-O `current_version` 从中读取。动态库安装名保持 `@rpath/Honggo.dylib`；IPA 中仍嵌入 `Frameworks/Honggo.dylib`，不会同时加载多个版本。

1.0.5 的设备构建和产物需要本版本 CI 的行为与图像门禁放行，实际结果见对应提交的 [GitHub Actions](https://github.com/SOLHK/Honggo/actions)。原始红果 IPA 尚未取得；交付范围为版本化动态库、预处理工具和说明。待签名 IPA 需要提供原始宿主包后生成，再由用户重签。受控 UIKit 模拟器的结果不等于真实红果的真机验收。
