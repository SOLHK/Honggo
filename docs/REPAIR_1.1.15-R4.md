# Honggo 1.1.15-R4：独立实现设置增强与兼容边界

## 目标与依据

用户要求研究 [NaiwaGuo](https://github.com/XIaodou0416/NaiwaGuo/tree/9e81c0008fe4e7b506b1cd747a93022846ccf08a) 的功能和思路，禁止复制作者代码。参考研究人员只提供行为规格和设计观察，生产实现基于 Honggo 自己的现有源码和公开系统接口。没有导入参考源码、资源、预设或代码片段。完整功能对照见 [研究记录](REFERENCE_STUDY_NAIWAGUO.md)。

变更基准为 Honggo `770112cb9bf7d7ce5caa97afebedb206909836a7`。宿主范围仍为 `Eggplant`、构建 `7.4.3.33`，最低 iOS 15.0.1、arm64。本轮保留既有广告规则和玻璃启动策略，不扩大宿主版本或宣称未来 iOS 自动兼容。

## 用户可见变化

### 搜索与清楚的操作入口

设置使用系统 `UISearchController` 搜索 16 个现有功能及诊断、配置工具。功能名、标识和常用位置别名来自同一个元数据表；多词匹配需要每个词都出现。结果通过稳定的功能标识操作偏好，不会因为筛选后行号变化写错开关。

无结果时显示明确提示，列表支持系统字体大小。搜索结果中的导出、导入、重置和兼容页面跳转等待搜索控制器收起后执行，避免两个控制器竞争展示。

### 只管理 Honggo 功能开关的备份

`Preferences.m` 统一原有枚举、名称和设置键，保持所有 `HongguoGlass.*` 键不变。备份格式为 `Honggo.preferences`、schema `1`，导出 16 个功能开关和插件版本。文件由系统分享面板保存或发送，没有网络服务。

恢复使用系统 JSON 文件选择器；协调读取在后台完成，实际读取限制为 64 KiB 加一个用于检测超限的字节。解析严格检查文档结构、格式、schema、已知字段和 JSON 布尔值。整个输入通过校验后才显示变化数量，用户确认后写入；写入接口自身再次完整校验，拒绝不合规输入，不因部分字段合法就部分恢复。

部分备份仅修改列出的已知功能，未列出的保持当前值。未知功能、其他应用的备份、错误类型和过大输入全部拒绝。“关闭全部功能开关”仅写这 16 项为关闭。两类操作均不修改宿主账号、其他偏好、日志或增强诊断授权。

### 本次启动兼容状态

设置页按设置入口、底栏、按钮、广告和基础检查展示当前适配记录。诊断日志包含有界 `runtime` 快照，记录模块、状态、类/方法、预期和实际签名及跳过原因，不包含对象地址、页面文字、账号或网络请求。

这些是入口安装检查。用户修改开关后仍须完全退出再打开；本次快照不伪装成下一次启动状态，也不代表广告或外观已经完成真机验收。

## 修复的工程问题

- 广告安装曾受底栏安装结果限制。现在独立安装各模块，底栏缺少必要接口时不会阻止已匹配的广告规则。
- 方法入口增加空值、类型、重复安装及已有替换状态检查。保留按目标类替换的方式，继承方法只在目标子类上覆盖，不污染父类。
- 按钮安装按目标记录，可在有界启动重试中补上初次未就绪的类；重复调用不把自己的替换保存为原方法。
- 动态对象 getter 在发送消息前验证无额外参数且返回对象，避免把整数或结构体误当作对象。无法确认时返回空结果并保留宿主行为。
- 重试限制在启动阶段，不引入永久轮询、全局类扫描或热路径日志风暴。

## 验证与限制

本轮增加 Foundation 配置测试、UIKit 搜索/操作回归和 runtime 边界测试，保留原有广告、设置入口、底栏和现场诊断验证。设备构建仍使用 ARC、系统库、`-Wall -Werror` 和 iOS 15.0.1 部署目标。每份远程产物保留插件版本、源提交和 SHA-256。

验证结果在提交和 CI 完成后记录于交付说明及对应 Actions 运行。当前开发环境没有 Xcode；本地脚本检查和 Python 测试不能代替远程 iOS 编译。真实红果设备上的页面、系统文件选择器、玻璃显示、连续播放、广告拦截及开关恢复仍需设备验收。

已有的 `com.apple.SwiftUI.IgnoreSolariumOptOut` 进程参数不是公开的兼容承诺；本轮未改变它。关闭两个玻璃开关并重启后的恢复、旧系统模糊回退仍按 README 检查。

后续字体、图标、播放布局和复杂面板定制必须逐项补充 Honggo 自己的宿主适配证据，不使用参考项目未验证的私有接口作为成功依据。
