# Honggo 1.1.15-R11 — 播放器移交、全集圆角与底部遮罩

基线：已发布 R10，`1b21dbb4db5ddefd6a02013e6a2dbff04943b2c2`。继续适配红果 7.4.3 / Eggplant 7.4.3.33，使用 Xcode 27.2、iPhoneOS SDK 27.2 和固定 iOS 27.2 模拟器构建门槛。

## 本次证据

用户反馈 R10 竖屏铺满视频进入全集仍会卡住，全集按钮露出方形四角，浮动底栏附近的遮罩和内容边界不自然。

新日志来自 R10 / iOS 27.3，包含 1,209 条事件、三个进程会话，没有事件丢弃或容量裁剪。58 组播放诊断全部有进入和返回：模型更新 15、状态更新 8、结束判断 35；结束判断均返回不拦截。87 条贴片展示记录为转交宿主。187 条播放器迁移事件均记录 `fullscreen=true`。前两个会话的尾部都落在播放器移出或挂入容器的阶段，随后出现新进程会话。

迁移日志原来写在插件预处理完成之后、宿主原方法调用之前。因此最后的迁移事件不能证明预处理本身卡死，也不能证明宿主原方法已经返回。日志没有线程栈、终止原因、解码帧进度或全集点击标记，不能据此宣布唯一根因。现有 hook 安装器的继承方法、重复安装和多模块串接未发现确定的自递归路径；本次不修改广告判定和播放业务回调。

现场明确显示 `TTPlayerView → TTMetalView`；全集入口是单个 `FQVShortVideoBaseInsertView → SSShortVideoBottomDistributionView → SSShortVideoDistributionContentView`，入口为 440×44。浮动底栏开启时 `SSTabBar` 仍有宿主全屏 mask。两份视图树到达节点上限，没有全集页面卡死瞬间的快照。仅保存上述脱敏统计，原始日志和截图不提交仓库。

## 播放器移交

R9/R10 虽然减少了重复缩放写入，仍通过 `TTPlayerView.transform` 放大整个播放器。宿主随后按 `frame` 布局或在全集页面复用播放器时，非单位变换仍可能干扰原布局。Apple 对 [UIView.frame](https://developer.apple.com/documentation/uikit/uiview/frame) 明确说明：存在非单位视图变换时，不能使用该 frame 进行布局修改。

R11 对本次现场已识别的单个 `TTMetalView` 渲染子树使用父层的 `sublayerTransform` 完成等比放大和平移，不改播放器或外层页面的 `frame`、`bounds`、`center`、`UIView.transform`。若渲染结构未知、混入其他内容、宿主有自定义渲染变换或 layer mask，则保留原生显示。填满期间需要释放的仅是当前渲染容器自身的裁剪，原生外层页面继续决定分页边界。

渲染变换和裁剪有独立所有权记录，在播放器或整页迁移前释放；宿主后续写入优先。转场完成、取消、复用与旧完成回调均按当前容器和代次校验。迁移诊断增加阶段信息，渲染填满诊断只在状态变化时记录，帮助区分原方法未返回与渲染回退。

## 全集入口四角

旧版只给玻璃子视图加圆角；原生内容层和插入容器仍可能保留矩形底色。R11 将已识别的入口、同尺寸内容层、只包含此入口的插入容器统一为胶囊圆角，并清理这两个已识别内部表面的背景色。

入口文字、图标、点击控件及布局位置由宿主管理。共享多个组件的插入容器和不认识的父视图不处理；移除、复用和关闭设置时恢复仍由插件持有的颜色及裁剪属性，后写入的宿主值保留。

## 自定义底栏遮罩

R10 的自定义底栏分支先恢复旧外观并提前返回，跳过了既有玻璃底栏对宿主 mask、背景和普通页面底部视口的处理。R11 让自定义底栏复用必要的宿主表面清理，避免残留全屏 mask 影响玻璃合成；普通列表延伸到窗口底部并补偿底部可滚动留白，消除书库底部的固定硬边。

竖向分页视频和包含它的祖先不参与视口延伸，保证原生单页高度、内容偏移和切集判断不变。截图中一整页向上移动、下一页逐渐出现也可能是正常滑动过程，不能把这部分一概遮掉。

## 验证与边界

- 播放器回归加入真正按原始 frame 校正尺寸的受控宿主，验证渲染填满时宿主视图几何仍完全不变。
- 覆盖画面填满与全集玻璃的四种组合、点击只执行一次、同窗口迁移、整个播放页迁移、返回和取消转场，以及未知渲染结构和宿主后写入值。
- 全集回归使用实际三层宿主结构和不透明内容，检查四角像素透明、点击区域、重复布局、开关恢复、共享容器和复用。
- 底栏回归覆盖宿主 mask 清理与恢复、列表底部延伸和 inset 稳定、视频及祖先分页尺寸保持，以及插件自身玻璃和选中背景保留。

完整发布工作流必须在同一提交上通过既有门槛后才构建设备 dylib 并发布预发行版；具体通过数量以 Actions 证据为准。受控 UIKit 宿主没有运行红果真实网络播放和解码，不能替代用户 iPhone 的复现验收。发布资产继续包含 `source-commit.txt`、`VERSION`、构建环境和 `SHA256SUMS.txt`。

真机复测保留原外观配置，先测试“竖屏满屏 → 观看全集 → 返回 → 换剧重复”，再观察全集四角、书库底部、底栏点击及清屏倍速自动下一集。若仍卡住，下一份日志将能更细地区分布局与迁移阶段。
