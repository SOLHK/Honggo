# Honggo 1.1.15-R10 — 独立按钮图标的玻璃层级修正

R10 延续 [R9 全集跳转布局保护与灰色底栏](REPAIR_1.1.15-R9.md)。基线是 R9 提交 `e0043fc233f16334f2955c1f60f8f498315462fd`。本次补充修正来自同一轮实际渲染核查，按源码变更必须递增测试版本的约定顺延至 R10。

## 实际渲染发现

R9 的主要外观检查 170/170、外观参数 36/36 已通过。初次窗口预览落在底栏展开动画中间；仅修改测试等待方式、保持全部 `src` 内容一致的独立验证，在 Xcode 27.2 / iOS 27.2 上通过 171/171 检查。动画结束后的截图已能看到完整灰色选中块与白色主图标，但独立「我的」图标明显发虚。

独立按钮本身是 `UIButton`，玻璃效果也是它的子视图。设置按钮 configuration 时，UIKit 可以重排自身的内容视图，使玻璃实际合成在图标前方。单独对按钮 layer 进行的图片颜色检查没有覆盖这个窗口合成问题。

## 修正范围

仅在插件自己创建的独立按钮、展开按钮上，把玻璃材质放到前景内容后方。宿主控件的顺序保持由宿主管理；不恢复 R8 反复抢占子视图第一个位置的做法。R9 的播放器几何移交、转场完成/取消处理、灰色选中背景和图标比例继续保留。

## 新的验证要求

- 截图前等待底栏展开动画完成，并要求连续两帧的模型和实际呈现几何一致；等待有明确上限，不阻塞主线程睡眠。
- 使用实际窗口截图检查独立按钮白色图标的前景亮度，补足只渲染单个 layer 的覆盖缺口。
- 保留所有原有外观断言、配置检查及发布门槛。预览文件统一为 `dock-preview.png`，图上使用实际版本号。
- 新版仍须通过完整 test 发布工作流，再构建和发布 arm64 dylib；R9 的结果不能代替 R10 的检查。

## R9 底栏构建未发布的原因

R9 工作流 `43725070804` 的设置、外观、运行时、诊断及广告检查均通过。底栏对照中，当前实现 121/121、启动覆盖路径 123/123 通过，但 fallback 深色场景的 `xcrun simctl io screenshot` 超过 55 秒，未能向测试应用返回截图确认。该场景因此按原断言失败，缺少深色系统截图；工作流随后达到 20 分钟时限而取消，设备构建和发布被跳过。

R10 为这个已观察到的截图传输超时增加有界重试：每次使用独立临时图片，只将成功、有效且仍对应当前场景的截图确认为完成。测试应用的等待窗口与两次截图尝试相匹配，底栏任务总预算改为 30 分钟。13 组场景、深浅色截图、像素对比和原有负向对照继续全部执行；没有把失败截图当作通过，也没有降低图像判定门槛。

验证采用受控 UIKit 宿主，没有运行真实红果 IPA。竖屏点击全集、返回、继续播放，以及用户手机上的 iOS 27.3 玻璃效果仍需真机复测。
